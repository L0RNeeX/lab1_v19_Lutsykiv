# Лабораторна робота 1 — Кінотеатр

Курс «Кросплатформні засоби програмування». Варіант **19**, рівень **1**.

Програма читає відомості про кіносеанси, перевіряє кожен рядок, обчислює чотири показники та формує однаковий текст звіту в консолі й файлі. Хибні рядки пропускаються з поясненням причини та номера рядка.

Обсяг відповідає базовому рівню з методичних вказівок: Java-код, дані, Javadoc, README і REPORT. Maven, JUnit, статичний аналізатор, JAR, Issues/PR та CI належать до наступних рівнів (методичка, с. 15, 22–23).

## Що потрібно встановити

- **JDK 21** або новішу JDK із підтримкою компіляції `--release 21`. Для однакових умов рекомендується саме JDK 21. Потрібні обидві команди: `java` і `javac`.
- Редактор тексту; зручно відкрити всю папку проєкту у VS Code.
- Git і обліковий запис GitHub — для публікації репозиторію за умовою роботи.

JDK можна встановити з [офіційного сайту Eclipse Temurin](https://adoptium.net/temurin/releases/?version=21). Виберіть свою ОС, архітектуру та пакет **JDK**. Після встановлення закрийте й знову відкрийте термінал. Якщо `java` або `javac` не знайдено, перевірте, що каталог `bin` установленої JDK додано до `PATH`.

## Швидкий запуск у Windows PowerShell

Розпакуйте архів. У VS Code виберіть **File → Open Folder**, відкрийте папку `kzp-lab01-variant19`, потім **Terminal → New Terminal**. Команди потрібно виконувати в папці, де містяться `README.md`, `src` і `data`.

Найкоротший запуск через готовий скрипт, який сам компілює програму:

```powershell
.\run.cmd
.\run.cmd --help
```

Для покрокового запуску та скріншота компіляції виконайте:

```powershell
chcp 65001
java -version
javac -version
New-Item -ItemType Directory -Force build/classes | Out-Null
javac -encoding UTF-8 --release 21 -d build/classes src/main/java/Lab01.java
java "-Dfile.encoding=UTF-8" -cp build/classes Lab01
```

Успішна команда `javac` зазвичай нічого не друкує. Після запуску програми звіт з'явиться в консолі та у файлі `out/report.txt`.

Довідка:

```powershell
java "-Dfile.encoding=UTF-8" -cp build/classes Lab01 --help
```

Власні шляхи до файлів:

```powershell
java "-Dfile.encoding=UTF-8" -cp build/classes Lab01 --input data/valid.csv --output out/valid-report.txt
```

Перевірка файла, у якому немає коректних записів:

```powershell
java "-Dfile.encoding=UTF-8" -cp build/classes Lab01 --input data/invalid.csv --output out/invalid-report.txt
```

Для шляхів із пробілами потрібні лапки:

```powershell
java "-Dfile.encoding=UTF-8" -cp build/classes Lab01 --input "C:/Навчання/Мої дані/input.csv" --output "C:/Навчання/Мої звіти/report.txt"
```

## Запуск у macOS і Linux

Відкрийте термінал у корені розпакованого проєкту. Готовий скрипт компілює й запускає програму:

```bash
sh ./run.sh
sh ./run.sh --help
```

Ті самі кроки вручну:

```bash
java -version
javac -version
mkdir -p build/classes
javac -encoding UTF-8 --release 21 -d build/classes src/main/java/Lab01.java
java -Dfile.encoding=UTF-8 -cp build/classes Lab01
java -Dfile.encoding=UTF-8 -cp build/classes Lab01 --help
java -Dfile.encoding=UTF-8 -cp build/classes Lab01 --input data/invalid.csv --output out/invalid-report.txt
```

Команди не потребують Maven або зовнішніх Java-бібліотек. Після зміни `.java`-файла повторіть компіляцію. Після зміни лише CSV повторна компіляція не потрібна.

## Формат вхідних даних

Текстовий файл UTF-8, один сеанс на рядок, роздільник `;`, **без заголовка**:

```text
film;hall;ticketPrice;sold;durationMin
```

Цей рядок показує порядок полів і не входить до самого CSV.

| Поле | Тип | Зміст і перевірка |
|---|---|---|
| `film` | `String` | Непорожня назва фільму після обрізання крайніх пробілів |
| `hall` | `int` | Номер залу, більший за нуль |
| `ticketPrice` | `double` | Скінченна ціна квитка від нуля, десятковий роздільник — крапка |
| `sold` | `int` | Кількість проданих квитків від нуля |
| `durationMin` | `int` | Тривалість у хвилинах, більша за нуль |

Додатність `hall` і `durationMin` — прийняте предметне уточнення реалізації: у таблиці варіантів окремих числових меж немає. Нульова ціна допустима для безкоштовного сеансу; `sold = 0` означає, що квитки ще не продано. Такий запис бере участь у середній ціні.

Порожні рядки, порожні поля, зайві або відсутні поля, неправильні числа, від'ємні значення, `NaN` та нескінченність не потрапляють до статистики. Поля з `;` усередині назви та CSV-екранування лапками не підтримуються: умова передбачає простий розділений текст.

Приклад:

```text
Місто світла;1;150.00;80;100
Подорож Карпатами;2;180.00;60;120
Таємниця озера;1;120.00;50;95
Космічна пригода;3;160.00;40;110
Ранковий сеанс;2;100.00;0;60
```

Назви й значення в прикладі є навчальними даними.

## Обчислення

Для `N` коректних сеансів:

1. Кількість коректних записів: `N`.
2. Загальний виторг: сума `ticketPrice * sold` для всіх коректних записів.
3. Середня ціна квитка: сума `ticketPrice`, поділена на `N`.
4. Найбільша кількість проданих квитків: максимум `sold` серед коректних записів.

Середню трактовано як **арифметичне середнє поля `ticketPrice` за сеансами**. Це узгоджується з поясненням методички про показники числових полів (с. 15); кількість проданих квитків не є вагою для середнього.

Для наведених п'яти сеансів:

```text
Виторг = 150 × 80 + 180 × 60 + 120 × 50 + 160 × 40 + 100 × 0 = 35200.00 грн
Середня ціна = (150 + 180 + 120 + 160 + 100) / 5 = 142.00 грн
Максимум проданих квитків = 80
```

Якщо коректних записів немає, програма показує кількість `0`, виторг `0.00`, а середню ціну та максимум позначає словами «немає даних». Ділення на нуль не виконується.

Для навчальної роботи використано передбачений варіантом `double` і форматування до двох знаків. Це демонстрація базової обробки даних, а не бухгалтерський облік із точними десятковими сумами.

## Самоперевірка

| Сценарій | Очікуваний результат |
|---|---|
| Звичайний запуск | 5 коректних, виторг 35200.00, середня 142.00, максимум 80, 5 пропущених рядків |
| `--help` | Опис параметрів; читання даних не потрібне |
| `--input data/valid.csv` | Ті самі чотири показники, помилок немає |
| `--input data/invalid.csv` | 0 коректних; усі хибні рядки пояснено; «немає даних» для середньої та максимуму |
| `--input data/empty.csv` | 0 коректних, виторг 0.00, «немає даних»; без аварії |
| Відсутній файл | Зрозуміле повідомлення про помилку читання |
| `--input` без шляху | Повідомлення про помилкові аргументи |
| Українські назви | Український текст читається й зберігається у UTF-8 |

Для перевірки незалежності чисел від локалі:

```bash
java -Dfile.encoding=UTF-8 -Duser.language=uk -Duser.country=UA -cp build/classes Lab01
```

Очікувані числові рядки залишаються `35200.00` і `142.00` із крапкою.

**Перевірка підготовленого пакета:** у Linux із Temurin JDK 21.0.13+9 пройдено 20 із 20 перевірок. Компіляція з `-Xlint:all` і генерація Javadoc завершилися без попереджень. Перевірено обчислення, збіг консольного та файлового звітів, порожні й хибні дані, локаль, UTF-8, параметри запуску та захист вхідного файла. Докладні результати — у `examples/verification-results.txt`. Це перевірки середовища підготовки; скріншоти для здачі зробіть на власному комп'ютері.

Після обробки доступного файла програма повертає код `0`, навіть якщо всі його рядки хибні; причини наведено у звіті. Помилки читання/запису дають код `1`, помилкові аргументи — `2`. Параметр `--help` потрібно передавати окремо. Повторення `--input` чи `--output` не дозволяється; запис звіту поверх вхідного файла також заборонений.

## Публікація на GitHub

За методичкою репозиторій має бути **публічним**, а назва — містити номер роботи й прізвище. Приклад: `kzp-lab01-petrenko`. Створіть на [GitHub](https://github.com/new) порожній репозиторій із видимістю **Public**. На цьому етапі не додавайте через сайт README, `.gitignore` чи ліцензію: локальні файли вже підготовлені.

У терміналі в корені проєкту виконайте:

```bash
git init
git add .
git commit -m "Complete lab 01 variant 19 level 1"
git branch -M main
git remote add origin https://github.com/LOGIN/kzp-lab01-SURNAME.git
git push -u origin main
```

Перед виконанням замініть `LOGIN` і `SURNAME` фактичними значеннями або скопіюйте точну адресу свого репозиторію. Git може попросити налаштувати ім'я/електронну адресу автора або пройти автентифікацію. Після `push` відкрийте сторінку репозиторію та перевірте наявність `src`, `data`, README і REPORT. Підставте реальне посилання у звіт.

Не додавайте лише архів ZIP: у репозиторії мають бути доступні окремі вихідні файли. Папки `build` і `out` не потрібно зберігати в Git — їх відтворюють команди запуску.

## Що заповнити перед здачею

1. У `REPORT.md` та `REPORT.docx` замінити поля ПІБ, групи, ОС і посилання на GitHub.
2. Повторити запуск на своєму комп'ютері та додати власні скріншоти за `SCREENSHOTS.md`.
3. Переглянути весь код і пояснення; сформулювати особисту відповідь на контрольне питання 21.
4. Зберегти фактичний опис участі ШІ. У підготовленому пакеті ChatGPT генерував код і документацію; не замінювати це твердженням про повністю самостійне написання.
5. Завантажити у ВНС звіт у DOCX або PDF із посиланням на репозиторій: сам `REPORT.md` не замінює цей файл (методичка, с. 22).

Методичка (с. 19) передбачає самостійне написання коду з консультативною допомогою ШІ. У цьому пакеті обсяг допомоги більший, тому його потрібно чесно зазначити та узгодити допустимий спосіб використання з викладачем. Пояснення коду й власна перевірка потрібні для захисту.
